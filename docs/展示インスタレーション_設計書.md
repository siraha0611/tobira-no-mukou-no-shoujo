# 『扉のむこうの少女』展示インスタレーション 設計書

作成: 2026-07-08 ／ 対象: 展示会場に実物の扉を設置し、「扉のむこうから少女が話しかけてくる」体験を無人運転する

---

## 1. コンセプト

来場者が古い扉の前に立ち、話しかけると——扉のむこうから少女(綾香)の声がこたえる。
会話するほど彼女は記憶を取り戻し、じゅうぶんに思い出すと扉が光り、ひらく。

- **Webアプリ本体がそのまま展示の頭脳になる**。専用ソフトは不要。
- 本番URLに `?mode=exhibit` を付けて開くだけで展示モードが起動する。

```
https://tobira-no-mukou-no-shoujo-web.anb14625siraha.workers.dev/?mode=exhibit
```

## 2. 展示モードの動き(実装済み)

1. **設営者が一度だけ「展示をはじめる」を押す**(音声の解禁・全画面・画面スリープ防止)。画面にセルフチェックが出る(音声認識/サーバ/ローカル音声合成)。
2. **待ち受け**: 「とびらの前に立って、話しかけてみてください」の文字がゆっくり明滅。マイクは常時待機。
3. **来場者が話しかけると自動でセッション開始**。オープニングの声→来場者の第一声に少女が応答。
4. **ハンズフリー会話**: 少女が話しおわると自動でマイクが開き、来場者が話しおわる(約2秒の間)と自動で届く。ボタン操作は一切不要。
5. **結末**: 扉がひらく演出(光・リング・鈴の音)→「— 扉は、ひらきました —」→ 18秒後に自動で初期化、次の来場者を待つ。
6. **立ち去り検知**: 110秒無応答なら「……また、あそびに、きてくださいね」と言って自動リセット。
7. **自己回復**: マイクが落ちたら4秒ごとに自動で立て直し。通信エラー時も聞き直して待つ。

### URLパラメータ

| パラメータ | 既定 | 意味 |
|---|---|---|
| `mode=exhibit` | — | 展示モードを有効化(必須) |
| `idle=110` | 110秒 | 無応答でお別れするまでの秒数 |
| `rest=18` | 18秒 | 結末後、次の来場者を待つまでの秒数 |
| `ttsbase=http://127.0.0.1:10101` | AivisSpeech | ローカル音声合成エンジンのURL(VOICEVOX互換) |
| `speaker=` | 自動検出 | ローカル音声合成のstyle_id(未指定なら先頭モデル) |

### 運転席(オペレーション)

- **左上のロゴを5回タップ** → 操作パネル(文字入力・設定)が出る。マイク不調時は手動代行も可能。
- とめるときはタブを閉じる。再開はURLを開いて「展示をはじめる」を押すだけ。

## 3. 声の経路(3段フォールバック・実装済み)

1. **ローカルAivisSpeech Engine**(`http://127.0.0.1:10101`) — **無料・低遅延・従量課金なし。展示の本命**。展示PCでAivisSpeechアプリを起動しておくだけ。
2. クラウドAivis(/tts経由・コハク「せつなめ」) — ローカルが無いとき。**従量課金 ¥440/万字**、日次上限15,000字で自動停止→次へ。
3. ブラウザ内蔵音声(speechSynthesis) — 最後の砦。品質は落ちるが止まらない。

> 推奨: 展示は**ローカル一択**で運転(コストゼロ)。AivisSpeechに綾香に合う声モデルを入れておく。`speaker=`で指定可。

## 4. 機材構成

```
[実物の扉(化粧扉・パネル扉)]
   ├─ 裏側: スピーカー(扉のむこうから声がする要)
   ├─ 表側上部 or 扉前: 単一指向性マイク(来場者の声を拾う)
   └─ 脇 or 裏: ノートPC(Mac) — Chrome + AivisSpeech
        └─ (任意) 小型モニタ/プロジェクタで字幕・扉の光の演出を投影
```

| 品目 | 目安 | 備考 |
|---|---|---|
| 扉(建具の中古・DIYパネル) | ¥5,000〜15,000 | 蝶番で自立枠に。実際に開く必要はない(光で表現) |
| スピーカー(小型・有線) | ¥3,000〜8,000 | 扉裏に隠す。Bluetoothは遅延と混線があるため**有線推奨** |
| 単一指向性マイク(USB) | ¥4,000〜10,000 | 会場の環境音対策の要。ダイナミック型が理想 |
| ノートPC | 手持ちのMac | Chrome必須(音声認識のため) |
| モバイルWi-Fi/テザリング | 手持ち | 脳(Claude API)はクラウドのため要ネット |
| (任意)小型モニタ | 手持ち | 字幕を出すと聴覚障害の方にも届く |

**合計 ¥12,000〜33,000**(既存構想メモの¥2〜3万と整合)。

## 5. 設営手順(当日)

1. 展示PCでAivisSpeechアプリを起動(メニューからエンジンが127.0.0.1:10101で立つ)。
2. Chromeで展示URL(`?mode=exhibit`)を開く。
3. マイク許可を「常に許可」で与える(URLがhttpsなので記憶される)。
4. セルフチェック3項目が「✓✓✓」(ローカル音声合成含む)になるのを確認。
5. スピーカー音量を実際に離れて聞いて調整(アプリ内「こえの大きさ」でも微調整可)。
6. **「展示をはじめる」を押す** → 待ち受けになったら、ひとことリハーサル(挨拶→応答→放置でお別れまで)。
7. PCの電源設定: 電源接続+ふたを閉じない配置(クラムシェルは画面ロックに注意)。

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 会場がうるさく誤認識する | 単一指向性マイク+マイクを扉に近づける/`idle`を短めに。最悪はロゴ5タップ→手動代行 |
| 少女の声をマイクが拾ってループする | 実装で対策済み(発話中はマイクを閉じる)。スピーカーとマイクを扉の裏表に分離配置 |
| ネットが切れる | 「……こえが、とおい」と言って聞き直す(実装済み)。テザリングに切替 |
| 日次上限に達する | §6のcap引き上げ。到達時は「扉が、まだ、うまくひらきません」と待ち受けに戻る(実装済み) |
| 来場者が何も話さない | 待ち受け文言が「話しかけて」と明示。看板でも補助(「扉に、話しかけてみてください」) |
| 複数人が同時に話す | 音声認識は混ざるが会話は破綻しにくい(綾香はどんな言葉も糧にする)。1人ずつの動線をつくると良い |
| 画面スリープ | Wake Lock取得済み+電源設定で保険 |
| クラウドTTS課金の暴発 | ローカル運転なら¥0。クラウドでも日次15,000字で自動停止(実装済み) |

## 8. 体験設計メモ(演出)

- 結末までは平均10〜15ターン(MIN_TURNS=8)。展示の回転は1人あたり5〜10分想定。
- 途中で立ち去っても「また、あそびに、きてくださいね」で美しく終わる=どこで切れても体験として成立。
- 扉の「ひらく」は光の演出(画面/プロジェクション)。物理的な解錠(ESP32+ソレノイド)は将来拡張(構想メモ参照)。
- 修了展で使う場合: 展示は`?pid=`なし=研究ログは残らない。記録したい場合のみ `&pid=EXH01` を付ける(研究モード併用可)。
